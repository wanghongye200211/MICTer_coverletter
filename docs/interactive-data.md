## Score conventions

- **Targeted iPSC.** Within each rollout, potential change and activity are divided by their respective Day 0 values and added with weights 0.8 and 0.2. The site displays the mean across rollouts. [Source score table](../assets/data/transition-score.csv)
- **EMT/MET.** The indicator uses a trailing 2.5-day window. Each of the 32 rollouts is divided by its own Day 7 value before averaging. The population can play from Day 0, and the score is available from Day 7. [Updated export](https://github.com/wanghongye200211/MICTer_coverletter/pull/4)
- **Pancreatic endocrine and cardiac differentiation.** Each rollout computes `S = 0.95 × Q + 0.05 × Action`, then divides `S` by its Day 0.5 value. The reported score averages 32 normalized rollouts. The population and score caches are separate outputs. The 0.1-day population frames use the original trained models, a 0.02-day integration step, and per-particle time calibration, with the earlier half-day snapshots reused unchanged. [Cache export](https://github.com/wanghongye200211/MICTer_coverletter/pull/2)

## Updating a cache

Each data script exposes its cache through the `window` variable referenced by [`dataset-config.js`](../dataset-config.js). `frames` stores ordered `{time, points}` records, `observed` stores the fixed reference coordinates, `measurementTimes` lists the actual observation times, and `curve` stores ordered records with time and score as the first two columns. The dense playback and observation times have independent grids. An optional `peakTime` can identify a selected local peak. The targeted iPSC cache also supplies the two component columns and the cover-letter text.

Keep the data script compatible with direct opening of `index.html`. When updating a cache, check its time units, projection label, frame range, reference count, and score range. Update the script version in [`index.html`](../index.html) and the provenance above. The static figure bundle is versioned separately in the [asset manifest](asset-manifest.json).
